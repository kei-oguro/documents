- 改行区切りで数値が並んだ文字列の合計を簡単に得たい。
  - 結果的には、Google スプレッドシートに張り付けて選択すると、右下に合計や平均や個数や最小最大が表示されていた。
  - 実際にやったのは、vscode で改行文字を `+` に変換して python にコマンドラインで式を渡して print。
  - `fromclip|perl -nlE '$s+=$_; END{say $s}'` 標準入力から受け取った数値を合計して出力する。
    - `END{}` を初めて知った。`perl -n` は行単位で完結する処理にしか使えずに不便だと思っていたが、そういう仕組みがないワケがないよね。どうせまた覚えられない記号だろうと思って調べたことが無く、自前で `perl -e 'while(<>) {$s+=$_}print $s'` とやってた。
    - ちなみに `say` も初めて知った。
  - perl4 しかやってない僕としては、`use List::Util qw(sum)` せずにそのくらさせて欲しい。`reduce` も。
  - `awk '{s+=$1} END {print s}'` を覚えられると一番良い。
  - `paste -sd+ - | bc` paste コマンドは知らないが、bc は叩いてみてなかったので使わなかった。vscode で整形して bc は手軽で良い。実際今回はpythonでそれ。
  - が、`fromclip|perl -e 'print eval(join("+", <>))'` が僕にとって自然で、最初に思い付いたものでもある。
    - 次が while を使ったやはり perl のワンライナーだが、perl が入ってるかどうか確かめもしなかった。後で試したら入ってた。
  - perl で `<>` を配列コンテキストで使えるのがとても便利で、そうやってワンライナーを書ける手軽な言語はないの？と聞いたらいくつもあった。最初からそちらを教えて欲しい。
    - Ruby .. `ruby -e 'p ARGF.sum(&:to_i)'` または `ruby -e 'p ARGF.reduce(0){|s, x| s + x.to_i}'`
    - php .. `php -r 'echo array_sum(file(STDIN));'` これに限ればいい感じだけど、今から php を勉強する気にもなれない。
    - Raku .. `raku -e 'say lines.sum'` または `raku -e 'say [+] lines'` 。Raku は Perl6 だって。めちゃくちゃいいじゃん。perl5 で何をするにも use が必要になったのが先祖返りか。素晴らしい。調べてみてもいいかも。
    - python3 .. `python3 -c 'import sys; print(sum(map(int, sys.stdin)))'` import sys が不要だといいんだけどね。
    - Haskel .. `runhaskell -e 'interact $ (++ "\n") . show . sum . map read . lines'` これもなかなかだ。
    - node.js .. `node -e 'console.log(require("fs").readFileSync(0, "utf-8").trim().split("\n").reduce((a, b) => a + +b, 0))'` これやりたいんだが標準入力からの読み込みが `require("fs").readFileSync(0, "utf-8")` ではワンライナーで書く気に慣れない。そしてそこをラップするシェルスクリプトを書くと便利かも？
  - なんでコマンドラインから python にスクリプトを渡すのは `-e` じゃなくて `-c` なんだろうね？ >>> sh がそうだからだってさ。ruby も node も `-e` で php は `-r`。

Tips: [Unityで保存する度に確認ダイアログが毎回表示されていたが、設定個所は Preferences -> Asset Pipeline -> Verify Saving Asset だった](https://discussions.unity.com/t/why-does-the-save-assets-dialog-pop-up-everytime/436977/17)。

- Unity の外でファイルを .meta 毎コピーしたせいで GUID の重複で余分な差分が出る。それをした人がコミット忘れする。インポート後に git add したらいいのに、なんでただのコピーを push するの？

  - **僕のミス** で **濡れ衣** を着せてしまった。Unity の Auto Refresh の設定を Disable にするのを忘れたまま git の更新を掛けたら、ファイルのリネームで、移動後の新しい方を作った後に、移動前のファイルを何故か復活させていた。それで復活したのが untracked にならないのも不可解だが、見てたのに僕が気付いてなかったの？

> zsh の場合はそのまま。例) `time command1 | command2 | command3`

リポジトリが巨大で git bash で改行するだけで遅い。プロンプト表示だろうと思ってスクリプトを見ると git rev-parse --short HEAD だけで同様の時間が掛かっている。git status よりは流石に速いが。git branch –show-current は瞬時に終わるので、HEAD のコミットハッシュが不要なプロンプト表示スクリプトをAI に書いてもらった。
```bash
get_fast_git_info() {
    local git_dir
    git_dir=$(git rev-parse --git-dir 2>/dev/null) || return

    local branch=""
    local state=""

    if [ -d "$git_dir/rebase-merge" ] || [ -d "$git_dir/rebase-apply" ]; then
        state="|REBASE"
    elif [ -f "$git_dir/MERGE_HEAD" ]; then
        state="|MERGING"
    elif [ -f "$git_dir/CHERRY_PICK_HEAD" ]; then
        state="|CHERRY-PICKING"
    elif [ -f "$git_dir/BISECT_LOG" ]; then
        state="|BISECTING"
    fi

    branch=$(git branch --show-current 2>/dev/null)

    if [ -z "$branch" ]; then
        branch="HEAD detached"
    fi

    echo " ($branch$state)"
}

# PS1（プロンプト表示）の設定（__git_ps1を置換）
PS1='\[\033]0;$TITLEPREFIX:$PWD\007\]\n\[\033[32m\]\u@\h \[\033[35m\]$MSYSTEM \[\033[33m\]\w\[\033[36m\]`get_fast_git_info`\[\033[0m\]\n$ '
```
