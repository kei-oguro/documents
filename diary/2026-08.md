リポジトリが巨大で git bash で改行するだけで遅い。プロンプト表示だろうと思ってスクリプトを見ると git rev-parse --short HEAD だけで同様の時間が掛かっている。git status よりは流石に速いが。git branch –show-current は瞬時に終わるので、HEAD のコミットハッシュが不要なプロンプト表示スクリプトをAI に書いてもらった。
```bash
get_fast_git_info() {
    local git_dir
    git_dir=$(git rev-parse --git-dir 2>/dev/null) || return

    local branch=""
    local state=""

    if [ -d "$git_dir/rebase-merge" ] || [ -d "$git_dir/rebase-apply" ]; then
        state="|REBASE"
    elif [ -f "$git_dir/MERGE_HEAD" ]; then
        state="|MERGING"
    elif [ -f "$git_dir/CHERRY_PICK_HEAD" ]; then
        state="|CHERRY-PICKING"
    elif [ -f "$git_dir/BISECT_LOG" ]; then
        state="|BISECTING"
    fi

    branch=$(git branch --show-current 2>/dev/null)

    if [ -z "$branch" ]; then
        branch="HEAD detached"
    fi

    echo " ($branch$state)"
}

# PS1（プロンプト表示）の設定（__git_ps1を置換）
PS1='\[\033]0;$TITLEPREFIX:$PWD\007\]\n\[\033[32m\]\u@\h \[\033[35m\]$MSYSTEM \[\033[33m\]\w\[\033[36m\]`get_fast_git_info`\[\033[0m\]\n$ '
```

git scalar はリモートリポジトリには影響を与えずに、手元だけで働く。AI の要約は以下。

- Sparse Checkout支援: クローン時にデフォルトで有効化され、巨大なツリーから必要なディレクトリだけをサクッと展開できます。
- 不要なチェックの削減: インデックスのハッシュ計算スキップ (index.skipHash) や並列読み込み、ファイルシステム監視との連携で `git status` などのオーバーヘッドを削減します。
- バックグラウンド処理: コミットグラフの生成やプリフェッチ、パックファイルの再整理などを裏で非同期実行するため、フォアグラウンドのコマンド待ち時間を減らせます。
- 大規模向けデフォルト設定の自動適用: 通常は手動で個別に調整が必要な数十個の最適化設定（`gc.auto=0` や `fetch.unpackLimit=1` など）をワンコマンドで一元管理できます。
