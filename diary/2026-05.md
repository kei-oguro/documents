mxfp4 を非対応GPUで使った時に、int8 や fp16 に変換して転送するのか、mxfp4 で VRAM に転送して使用時に展開するのかを聞いてみたら後者だと言った。ということで gemma4 の mxfp4 版をダウンロードして同じプロンプトを試してみると少し遅くなったが誤差の範囲かも知れない。が、CPU に分担させるのをやめたら 5.5 tok/s で倍近く速くなった 。

一人暮らしではなかなか減らないので、6種類1つずつとか入った `プチっと鍋` のアソートタイプがあるといいと思っていた。久しぶりに思い付いて検索すると、6個入り1袋のものを10種類詰めたアソートならあった。

戻りに、目の前の `ほんとうにおいしいコーヒー` でエルサルバドルをテイクアウト。

python に setdefault() あるんじゃん。3行も書かなくても。

- 帰りに寄り道
  - 雨上がりな隅田川の水面が高い。永代橋を渡って川沿いを八丁堀方面へ歩く。月がデカい。
  - 八丁堀駅の東京駅寄りの一角を練り歩き、カレーイベントでよく見る `ワッカ` で晩酌。グリーンカレーと、小さいチキンカレーとラムキーマと、トンカツとメンチカツ。流石の美味しさ。メンチカツも素晴らしい。

コードの説明を求めて全く動きが無かった Qwen3.6-35B-A3B Q8_0 が回答を生成していた。トータル5分くらいだったらしいから、全く使い物にならないという程遅いワケでもない。量子化精度を落としたら、もっと早くなるかも知れない。また、CPU にも分担させられるかも知れない。

--n-cpu-moe 17 で CPU にも分担させたら遅くなった。揺らぎの範囲かも知れないが、gpt-oss-20B の時は CPU と分担したら倍速になったので、そういう効果がなさそうだとはいえるだろう。

Gemma4-26B-A4B-it Q8_0 をダウンロード。朝には終わるかな？
